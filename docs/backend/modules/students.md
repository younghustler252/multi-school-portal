# Students Module

> **Verification status:** Partially source-verified. Routes, controller, DTOs, query/create use cases, scope policy, mapper, import policy/use cases and DI registration were inspected. Remaining mutation use cases, photo service/repository, permission registry, schema/migrations and focused tests still require a complete pass.
> **Primary source:** `apps/api/src/modules/students/`
> **Route mount:** `/api/v1/students`, from `apps/api/src/routes/index.ts`.

## 1. Responsibility and boundaries

Owns a school's student record and lifecycle: directory/profile, creation and update, deactivation/reactivation, graduation reversal, branch transfer, private photo handling and CSV import. It does not create a global login during student creation. Student portal identity is a separate membership/invitation workflow.

## 2. Data and dependencies

Student data is tenant-schema data. The module uses a tenant repository, mapper, number-sequence service, private storage/photo service, Audit service and the Enrolment/Guardian modules for import workflows. Admission numbering uses the `students.admission_number` sequence and Nigerian time (`Africa/Lagos`) to determine the year. Generated numbers follow `YYYY/0001` and are allocated inside the student creation transaction.

Student photo storage is private: the database stores a storage path, not a public URL. The API response contains a short-lived URL (one-hour TTL) generated by StudentPhotoService.

## 3. Authorization and visibility

All routes require authentication and tenant context.

| Permission/persona | Scope behavior |
|---|---|
| `students.view` | `ALL`: all students; `BRANCH`: students in permitted branches; `ASSIGNED`: students enrolled this term in a class the staff member leads or teaches; `OWN`: the student's own record or a guardian's linked children |
| `students.manage` | Create, update, deactivate/reactivate, undo graduation and photo changes |
| `students.transfer` | Transfer a student between branches |
| `students.import` | Download template, preview CSV and import CSV |
| STUDENT persona | `GET /me` |
 
Every student read query applies `studentScopeWhere`. An out-of-scope ID is returned as not found, avoiding disclosure that the record exists. A requested `branchId` filter narrows the authorized result; it does not expand scope.

## 4. API endpoints

All paths are under `/api/v1/students`.

| Method and path | Access | Purpose |
|---|---|---|
| `GET /import/template` | `students.import` | Download CSV template |
| `POST /import/preview` | `students.import`, upload limiter, multipart field `file` | Validate and preview import; saves nothing |
| `POST /import` | `students.import`, upload limiter, multipart field `file` | Import valid rows |
| `GET /me` | STUDENT persona | Current student's own record |
| `GET /` | `students.view` | Paginated/searchable directory |
| `POST /` | `students.manage` | Create student |
| `GET /:id` | `students.view` | Read student within scope |
| `PUT /:id` | `students.manage` | Update student |
| `POST /:id/deactivate` | `students.manage` | Deactivate student |
| `POST /:id/reactivate` | `students.manage` | Reactivate student |
| `POST /:id/undo-graduation` | `students.manage` | Reverse graduation |
| `POST /:id/transfer` | `students.transfer` | Transfer to another branch |
| `POST /:id/photo` | `students.manage`, upload limiter, multipart field `photo` | Upload/replace private photo |

Photo and CSV uploads are limited to 2 MB. Upload routes re-establish tenant context after multipart parsing.

## 5. Request contracts

### CreateStudentDto

Strict object; unknown keys rejected.

| Field | Constraints |
|---|---|
| `firstName`, `lastName` | Required, trimmed, 1–50 chars |
| `middleName` | Optional, max 50 |
| `admissionNumber` | Optional, 2–30 chars; letters, numbers, hyphen, slash, dot, underscore |
| `dateOfBirth` | Optional valid past date |
| `gender` | Optional `male` or `female` |
| `bloodGroup` | Optional `A+`, `A-`, `B+`, `B-`, `AB+`, `AB-`, `O+`, `O-` |
| `address` | Optional, max 300 |
| `religion`, `nationality`, `stateOfOrigin` | Optional, max 50 each |
| `admittedAt` | Optional valid date, no more than 366 days in the future |
| `branchId` | Optional UUID; server resolves default branch if omitted |
| `confirmNotDuplicate` | Optional boolean |

### UpdateStudentDto

Strict partial update; at least one field. Optional fields can be cleared using `null` or blank string where DTO preprocessing permits. Admission number cannot be cleared.

### Other DTOs and query

- `DeactivateStudentDto`: optional `reason`, max 300.
- `UndoGraduationDto`: required `reason` (5–500 chars), `reopenEnrolment` defaults false.
- `TransferStudentDto`: required `toBranchId` UUID and reason (5–500 chars); optional `classId` UUID.
- `ListStudentsQuery`: page default 1, limit default 20 (max 100), optional search (max 100), gender, branchId; status is `active` (default), `inactive`, `graduated` or `all`.

## 6. Response projection

The Student mapper exposes `id`, `userId`, `admissionNumber`, names, date of birth, gender, blood group, address, `photoUrl`, religion, nationality, state of origin, `isActive`, lifecycle (`active | graduated | inactive`), `graduatedAt`, `admittedAt`, `branchId`, branch summary and `createdAt`. Private storage paths are never returned as `photoUrl`.

List response is `{ success, message, data, meta }`. Single-resource handlers use the shared success/created response helpers.

## 7. Business rules and workflows

- Plan student limit is checked on create and reactivate.
- Admission number is unique; automatic number sequence restarts each year in Nigerian time. Sequence allocation and student insertion share a transaction.
- A possible duplicate (same first name, last name and date of birth) requires explicit `confirmNotDuplicate`.
- Branch resolution is server-side: explicit branch, actor's own branch where applicable, otherwise main branch.
- Student reads always apply scope; out-of-scope reads look like not found.
- CSV import is implemented and routes are mounted. Preview writes nothing; preview and import share the same row-planning policy. CSV is capped at 2 MB and 1,000 rows. Required columns are firstName and lastName. Import can create class enrolments and guardian links as part of one tenant transaction; class seats are rechecked under lock. Plan capacity is checked for the full valid batch before writes.
- CSV import accepts CSV, not Excel workbooks. Birth dates accept `YYYY-MM-DD` or Nigerian day-first `DD/MM/YYYY`.
- Import template columns include student identity, admission number, class name and optional guardian details.

## 8. Frontend integration requirements

- Do not create a login as a side effect of student creation.
- Use returned `lifecycle` as well as `isActive`; graduation is a distinct lifecycle state.
- Treat admission number as server-generated when omitted.
- Render scope-limited results; do not attempt client-side authorization by downloading all students.
- Photo URLs are temporary; request fresh student data when a link expires. Never persist the private storage path.
- CSV import UI should have separate preview and commit steps and show row-level statuses/messages plus plan-limit outcome.
- Branch transfer is a dedicated audited workflow and requires a reason.
